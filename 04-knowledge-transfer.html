K0 · How the sessions run

A session is a working meeting, ninety minutes, screen shared, one laptop each. The rule is that whoever is learning drives for at least half of it: the outgoing engineer states the task, the successor performs it, the engineer watches and corrects. A session where only the engineer clicked has not transferred anything.

  • Before the session: both attendees read the page that covers the topic. Reading first is what makes ninety minutes enough.
  • During: one live task done by the successor, in a duplicate theme or the dry run, never on live pricing.
  • After: the artefact exists (a note, a fixed test suite, a filled table), and the session moves to "signed off" in K4. An artefact nobody wrote is a session that did not happen.
  • Recorded: no. These pages are the record, and each session's corrections go into them the same day.

Corrections go in the document, not into memory

If a step in page 1 or page 2 turns out to be wrong when the successor runs it, fix the page during the session. The document is the handover; a verbal correction dies with the call.

K2 · The five sessions

Session A · Storefront architecture and content editing

Pre-work: page 1, sections W0 to W4. Duration: 90 minutes.

  1. Walk the theme structure in the editor: which sections build the home page, what a JSON template is, why the header and footer are groups.
  2. Successor edits a homepage section in a duplicate theme and previews it, including the mobile view.
  3. Successor creates a product, adds it to an automated collection, and explains why the condition fills the grid rather than the product list.
  4. Colourway-as-product model: show the product.color_variant_products metafield and what breaks when a colourway is modelled as a variant instead.
  5. Close with the publish sequence from W1 and the rollback, said out loud by the successor.

Artefact: a list of the sections on the live home page, written by the successor, with the owner of each piece of copy.

Session B · Bundle builder, gifts and the cart

Pre-work: page 1, sections W5 and W7; page 2, section B4. Duration: 90 minutes.

  1. Trace one bundle from product page to cart: which script, which app endpoint, which document decides the price.
  2. Successor changes a tier in Discount Rules in a scratch group, then reads the resulting quote in a cart, then removes the scratch group.
  3. Free gift ladder: change a threshold in a duplicate theme, verify the ladder in the cart, then explain why an unreadable theme disables gifts rather than falling back.
  4. Failure drill: explain how the two-tees-instead-of-cap-and-tee bug happened and which test guards it.

Artefact: one cart screenshot taken by the successor, annotated with where each price came from.

Session C · Backer Program deep dive

Pre-work: page 2, sections B0 to B3. Duration: 120 minutes.

  1. Dashboard: read the five cards and the claim status table without help, then explain what "not in rules" means.
  2. Import a small CSV in dry run and read the result panel line by line.
  3. Claim lifecycle: walk a single claim from unclaimed to claimed on a test customer, then replay the finalise step to show idempotency.
  4. Campaign rules: show where the reward mapping lives and what the pivot check refuses.

Artefact: the claim states table from page 2, rewritten in the successor's own words with one real claim id per state.

Session D · Infrastructure, deployment and credentials

Pre-work: page 3, all sections. Duration: 90 minutes.

  1. Deploy the app to a preview (not production) and read the deployment log.
  2. Run the app test suite and the theme test suite; show the missing package.json and apply the fix, if the change is approved.
  3. Walk the access table row by row, confirming who holds each system today and what the successor will hold after.
  4. Health and cron checks: /api/health, the two crons, the webhook re-registration endpoints, and the egress probe.

Artefact: the access table on page 3 updated with the real transfer status of each row, plus a first successful preview deploy by the successor.

Session E · Fire drills

Pre-work: page 1, W9; page 2, B6; page 3, A4. Duration: 90 minutes.

  1. Roll back a theme publish, live, on a duplicate: publish deliberately, then publish the previous theme back.
  2. Re-register the orders-paid webhook and confirm the health endpoint reflects it.
  3. Rebuild the customer mirror from the dashboard button, then from the cron endpoint.
  4. Restore a malformed pricing document from the last good JSON and confirm quotes resume.

Artefact: a one-page incident card written by the successor: symptom, first check, first action, who to call.

K2b · Questions each session must leave answerable

These are the questions a successor should be able to answer without notes after the session. If any answer needs a lookup, the session is not finished.

  • After session A: where do I change the text of the announcement bar, and how do I check it reached customers?
  • After session A: why is a collection short of products, and what do I check first?
  • After session B: where does a bundle price come from, and why is it not a discount code?
  • After session B: what do the slot fields in Free gift do, and what should I change instead?
  • After session C: what does each claim state mean, and what do I do in each?
  • After session C: what happens when a backer pays an invoice the claim no longer matches?
  • After session D: what has to be true before I deploy the app, and who is allowed to author the commit?
  • After session D: where does each credential live, and which one expires?
  • After session E: the store looks broken. What do I do in the first two minutes?
  • After session E: how do I re-register a webhook and confirm it worked?
